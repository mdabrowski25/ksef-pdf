# @mdab25/ksef-pdf v1.2.0

This documentation-focused minor release makes the package easier to install
and use. No migration from 1.1.0 is required. Node.js 22+ and the CIRFMF 1.1.40
renderer baseline remain unchanged.

## Documentation changes

- A minimal, runnable XML-to-PDF quickstart with a filename, execution command,
  expected output, and synthetic sample invoice.
- Complete CommonJS, UPO, Base64, and custom-font examples.
- Tables of API parameters, return types, input encodings, and metadata options.
- Guidance on supplied verification URLs, offline QR1/QR2, PEF profiles,
  acquisition-date formatting, errors, and low-level compatibility APIs.
- Troubleshooting for module configuration, paths, XML encoding, unsupported
  documents, fonts, and missing metadata.
- The original Polish support advertisement, now including both
  [mdab.it](https://mdab.it) and the maintainer's LinkedIn link.

The XML quickstart now passes file bytes directly to the renderer, preserving
UTF-16 detection. Font examples register normal, bold, italic, and bold-italic
styles so invoice headings render without a missing-font-style error.

## Compatibility

Runtime source, exports, dependencies, and supported formats are unchanged.
Generated invoice footers display package version 1.2.0. The version change
means generated PDFs should not be compared byte-for-byte with 1.1.0.

The future documentation website is a separate project; this release does not
add a website or browser runtime.

## Validation

- Executed all seven JavaScript README examples directly, including the two
  metadata replacements, with UTF-8, UTF-16 LE with and without a BOM, and
  UTF-16 BE with a BOM: 28 executions passed.
- Verified custom-font rendering with all four font styles supplied through
  the documented VFS setup.
- Typechecking, ESM/CJS builds, all 16 runtime export checks, and rendering of
  all seven invoice layouts and both UPO versions through both module formats passed.
- Documentation links and release metadata checks passed. A fresh reader review
  found no blocking missing steps; the historical sample filename is now explained.
