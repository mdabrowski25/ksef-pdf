# @mdab25/ksef-pdf v1.1.3

This patch release updates the renderer to stable
[CIRFMF 1.1.46](https://github.com/CIRFMF/ksef-pdf-generator/releases/tag/1.1.46)
and corrects an amount-parsing integration issue for Node XML input. No migration
from 1.1.x is required.

## Changes

- FA(1), FA(2), and FA(3) VAT summaries use integer cents, avoiding floating-point
  precision loss when adding the XML net and tax amounts.
- Numeric whitespace is trimmed before sign detection. For example, an XML
  amount containing ` -1.23 ` remains `-1.23`; the unadapted upstream helper
  would produce `-0.77`. Excess fractional digits are rounded to cents with
  midpoint ties away from zero, rather than truncated. Malformed nonempty
  amounts are rejected.
- FA(3) corrected buyers include JST/GV flags and customer numbers without
  requiring contact details.
- A single intermediate shipping address is rendered in FA(1), FA(2), and FA(3).
- Missing PEF correction total sections are omitted, and an absent header
  payable amount is shown as a dash instead of `undefined`. A local null guard
  also handles an existing correction extension without `LegalMonetaryTotal`,
  which would still throw in upstream 1.1.46.
- Dated PEF correction references display slash-separated invoice numbers as
  plain text, rather than HTML entities such as `&#x2F;`. HTML escaping is
  disabled only for that translation's interpolation.
- Invoice-number whitespace, OSS tax separators, collective-correction
  quantities, settlement amount grouping, and RR/PEF header spacing are corrected.

## Effect on invoice amounts

The package renders the supplied XML. It does not calculate VAT rates, edit
source XML, submit invoices, or replace an application's tax-calculation rules.
The VAT summary takes the XML net and tax values and adds them for its displayed
gross amount; an explicit `0.01` tax value remains `0.01`. This update therefore
does not repair an amount that was already calculated incorrectly in source XML.

Applications must update their pinned dependency and deploy the resulting build
to receive the fixes. Previously generated or cached PDFs remain unchanged unless
the application explicitly regenerates them.

## Compatibility

Public exports, input/output formats, Node.js 22+, runtime dependencies, fonts,
resource policies, QR options, and Warsaw timestamp handling are unchanged.
Generated invoice footers identify package version 1.1.3; compare PDF content
and layout rather than byte hashes after upgrading.

Unreleased CIRFMF 1.1.48 metadata and watermark changes are outside this release.
The existing UPO `formatType` argument and the package's watermark exclusion
remain unchanged.

## Validation

Verified locally on Node.js 24.22.1:

- Typechecking and all 1,090 tests across 136 files passed, including 65 new
  regressions for the imported fixes and local adaptations.
- ESM/CJS builds and export smoke checks passed, rendering all seven invoice
  layouts and both UPO versions through both module formats.
- Documentation links and release metadata checks passed; `npm audit` reported
  no vulnerabilities. `npm pack --dry-run` contained the expected 21 files.
- Six pages from three synthetic PDFs passed visual review for clipping and
  overlap, with additional text-extraction checks using pypdf.

Node.js 22 remains supported; a local Node.js 22 run was not part of this
validation. The CI matrix covers Node.js 22 and 24.

See the [README](../../README.md), [changelog](../../CHANGELOG.md), and
[upstream ledger](../../UPSTREAM.md) for usage and release history.

KSeFCanvas integration was also checked with its current-main CLI in isolation:
eight scenarios and 30 extracted-PDF text assertions passed, including a
multipage invoice, negative cents, declared Stripe VAT, settlement residual VAT,
UPO, legal confirmations, and both PEF fixes. This did not change or deploy the
Canvas application. QR decoding and XML schema validation were not part of these
renderer checks.
